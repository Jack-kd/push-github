# 06 - 运行与构建

## 1. 环境要求

| 项目 | 要求 |
| --- | --- |
| JDK | Java 17 |
| Android SDK | `compileSdk 35`（`android.suppressUnsupportedCompileSdk=35` 已配置，可在 34 环境中构建但建议装 35） |
| Gradle | 8.5（由 Wrapper 自动下载，见 `gradle/wrapper/gradle-wrapper.properties`） |
| AGP | 8.2.2 |
| 操作系统 | Linux / macOS / Windows 均可；CI 使用 `ubuntu-latest` |

> 首次构建需要下载 Gradle 发行版与依赖，请确保网络可达 `services.gradle.org`、`dl.google.com`、`repo.maven.apache.org`。

## 2. 构建命令

在项目根目录（`/workspace`）执行：

```bash
# 完整 Debug 构建
./gradlew assembleDebug

# 完整 Release 构建（开启混淆 + R8）
./gradlew assembleRelease

# 仅编译（更快）
./gradlew compileDebugKotlin

# 运行 Lint
./gradlew lint

# 运行单元测试
./gradlew test

# 清理构建产物
./gradlew clean
```

产物输出位置：

- Debug：`app/build/outputs/apk/debug/app-debug.apk`
- Release：`app/build/outputs/apk/release/app-release.apk`

> Windows 使用 `gradlew.bat` 替代 `./gradlew`。

## 3. 在 Android Studio 中运行

1. 使用 Android Studio（推荐新版本，支持 AGP 8.2）打开项目根目录 `/workspace`。
2. 等待 Gradle Sync 完成（会自动使用 Wrapper 的 Gradle 8.5）。
3. 连接真机（推荐 Android 11+，便于"所有文件访问"授权），或创建模拟器（API 26+）。
4. 选择 `app` 运行配置，点击 Run（快捷键 Shift+F10 / Ctrl+R）。

> 建议使用真机测试：本应用依赖真实文件系统路径、SAF 目录选择与"所有文件访问"授权，模拟器亦可但权限流程体验不同。

## 4. 首次使用流程（运行验证）

应用启动后按以下顺序验证核心功能：

1. **首次启动**弹出配置弹窗：输入邮箱、用户名、GitHub Token（`Settings → Developer settings → Personal access tokens → Tokens (classic)`，勾选 `repo` 权限），点"确定"在线校验后自动保存。
2. 主界面输入仓库地址（如 `https://github.com/user/repo`）与分支（默认 `main`）。
3. 授予"所有文件访问"权限（应用会自动拉起系统授权页）。
4. 点击"上传源码"，选择本地文件夹（SAF）或手动输入路径 → 确认推送。
5. 观察"运行日志"面板的实时输出与底部进度条；结束后弹出系统通知并可在"推送历史"中查看结果。

## 5. 定时推送

- 入口：右上角菜单 → **定时推送**。
- 输入间隔小时数（如 24），点击"开始定时"。
- 实现：`WorkManager.PeriodicWorkRequest` 创建 `ScheduledPushWorker`，周期性执行与手动推送相同的 `GitHelper.pushSourceToRepo` 流程。
- 取消：同一弹窗内点击"取消定时"（内部调用 `WorkManager.cancelAllWork()`）。

> 注意：定时任务在后台运行，只能访问本地路径（`sourceUri` 为空）；依赖"所有文件访问"权限仍有效。

## 6. CI 流程（`.github/workflows/build.yml`）

GitHub Actions，`push`/`pull_request` 到 `main`/`master` 触发，两个 Job：

**Job 1：`lint`**
1. `actions/checkout@v4`
2. `setup-java@v4`（temurin 17）
3. `gradle/actions/setup-gradle@v4`（gradle 8.5）
4. `gradle wrapper` 生成 Wrapper
5. `./gradlew lint`
6. `./gradlew test`

**Job 2：`build`**（依赖 lint 成功）
1-4. 同 lint
5. `./gradlew assembleDebug`
6. `./gradlew assembleRelease`
7. 上传 `debug-apk` / `release-apk` 为 CI Artifact

环境变量：`GRADLE_OPTS="-Xmx4096m -Dorg.gradle.daemon=false"`。

> 项目当前**没有单元测试源码**（`test` 目录为空），`./gradlew test` 会直接通过；如需补充测试建议在 `app/src/test` 下添加。

## 7. 常见问题排查

| 现象 | 排查方向 |
| --- | --- |
| 构建下载依赖慢/失败 | 检查网络与代理；Gradle Wrapper 需访问 `services.gradle.org` |
| Release 打包失败 | 多为 R8 混淆缺失类，先看 `-ignorewarnings` 覆盖范围；可临时 `isMinifyEnabled=false` 定位 |
| "无法访问选择的文件夹" | SAF 目录树 Uri 无效或权限未持久化，重新选择文件夹 |
| 推送 500 / Internal Server Error | 大文件推送：已配置 `http.postBuffer=500MB`，若仍失败检查仓库单文件大小与网络 |
| "推送被拒绝：远程仓库有新的提交" | 远程分支落后，先手动同步/清空仓库再推送 |
| 定时推送不执行 | 确认已授予"所有文件访问"权限、未取消任务；WorkManager 受系统 Doze 影响，间隔可能延迟 |
| 权限未自动弹出 | 手动到 系统设置 → 应用 → PushGithub → 所有文件访问 授权后返回 |

## 8. 版本发布约定

- `versionCode` / `versionName` 在 `app/build.gradle.kts` 的 `defaultConfig` 中维护。
- 发布流程建议：`./gradlew assembleRelease` → 取 `app-release.apk` 签名发布（当前未配置 signingConfig，release 包为默认 debug 签名，正式分发需补充）。
