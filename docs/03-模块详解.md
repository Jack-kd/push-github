# 03 - 模块详解

所有源码位于 `app/src/main/java/com/jack/pushgithub/`，按包划分职责。包与目录的对应关系：

| 包路径 | 职责定位 | 主要文件 |
| --- | --- | --- |
| （根包） | 应用入口 | `MainActivity.kt` |
| `data` | 数据层：Room 持久化 + 加密配置 | `AppDatabase`、`ConfigRepository`、`RepoConfig`、`PushHistoryEntity`、DAO |
| `git` | JGit 推送/克隆 + SAF 文件复制 | `GitHelper`、`DocumentFileCopy` |
| `github` | GitHub REST API 封装 | `GithubApi` + `CommitInfo`/`FileInfo` |
| `network` | 网络工具、凭据验证、重试拦截器 | `NetworkUtils`、`GithubVerify`、`RetryInterceptor` |
| `notification` | 系统通知帮助类 | `PushNotificationHelper` |
| `platform` | Git 平台抽象（GitHub/GitLab/Gitee） | `GitPlatform` |
| `ui` | Compose UI 与主题 | `MainScreen`、`ConfigDialog`、`theme/*` |
| `viewmodel` | 业务中枢 | `MainViewModel`、`MainUiState` |
| `worker` | 后台定时推送 | `ScheduledPushWorker` |

---

## 1. 根包：应用入口 — `MainActivity.kt`

**职责**：唯一 Activity。

- `onCreate()` 中依次执行：
  1. 创建通知渠道（`PushNotificationHelper.createChannel`）。
  2. 设置软键盘 `SOFT_INPUT_ADJUST_RESIZE`。
  3. 注册**全局未捕获异常处理器**：写日志 + 崩溃信息入日志面板（debug 才含堆栈），并链式调用默认处理器。
  4. `enableEdgeToEdge()` + `setContent { PushGithubTheme { MainScreen(...) } }`。
- 在 `ON_RESUME` 生命周期事件中**自动检测"所有文件访问"权限**（Android 11+），没有则拉起 `Settings.ACTION_MANAGE_APP_ALL_FILES_ACCESS_PERMISSION` 授权页；授权返回后回调 `checkStoragePermission()` 刷新状态。
- 持有 `mainViewModel: MainViewModel by viewModels()`（`AndroidViewModel`）。

## 2. `data` 包：数据层

### 2.1 `AppDatabase.kt`
- Room 数据库，版本 `1`，`exportSchema = false`。
- 两个实体：`PushHistoryEntity`（表 `push_history`）、`RepoConfigEntity`（表 `repo_config`）。
- 暴露 `pushHistoryDao()`、`repoConfigDao()`。
- 数据库文件名：`push_github_db`（在 ViewModel 与 Worker 中分别 `Room.databaseBuilder` 创建）。

### 2.2 `ConfigRepository.kt`
- 负责 Git 凭据的**加密读写**。
- 使用 `EncryptedSharedPreferences`（文件名 `github_config_encrypted`，MasterKey AES256_GCM；键 AES256_SIV、值 AES256_GCM）。
- `GitConfig(email, username, token)` 数据类承载配置。
- 方法：
  - `loadConfig(): GitConfig`（IO 线程）
  - `saveConfig(config)`（IO 线程）
  - `hasConfig(): Boolean`（三项均非空）

### 2.3 `PushHistoryEntity.kt`
Room 实体，字段：`id`(自增主键)、`repoUrl`、`branch`、`sourcePath`、`success`、`timestamp`、`message`。

### 2.4 `RepoConfig.kt`
Room 实体，字段：`id`(自增主键)、`name`、`repoUrl`、`branch`、`createTime`。

### 2.5 `PushHistoryDao.kt`
- `getAllHistory(): Flow<List<...>>`（时间倒序）
- `getHistoryBySuccess(success): Flow<...>`
- `insert / update / delete`
- `clearAll()`
- `count(): Int`

### 2.6 `RepoConfigDao.kt`
- `getAllConfigs(): Flow<List<...>>`（createTime 倒序）
- `insert / update / delete`
- `getById(id)`

## 3. `git` 包：JGit 操作

### 3.1 `GitHelper.kt`（核心服务，object 单例）
提供两个顶层能力：
- `pushSourceToRepo(...)`：完整"推源码到仓库"流程（见架构文档 3.1）。
- `cloneDownload(...)`：克隆仓库到本地路径（带 `ProgressMonitor` 进度映射）。

内部支撑逻辑：
- `DEFAULT_IGNORE_PATTERNS`：内置忽略清单（`.git`、`build`、`.gradle`、`.idea`、`node_modules`、`.DS_Store`、`__pycache__`、`.env`、`local.properties` 等）。
- `.gitignore` 解析：`loadIgnoreRules()` 读取源目录 `.gitignore`，`compilePattern()` 将 gitignore 通配符（`*`、`**`、`?`、目录尾 `/`、取反 `!`）编译为正则 `IgnorePattern`；`shouldIgnore()` 判断是否忽略；`countFiles()`/`copyDirectory()` 按规则复制并回报进度。
- `configureRepoForPush(repo)`：限制 pack 内存（`pack.window=2`、`pack.depth=10`、`windowMemory=8m`、`deltaCacheSize=2m`、`deltaCacheLimit=30`、`bigFileThreshold=3m`、`threads=1`、`indexVersion=2`），加大 `http.postBuffer=524288000`（500MB）、关闭低速率限制，解决大文件推送问题。
- push 重试：HTTP 500 / Internal Server Error 时指数退避（attempt×3s）最多重试 3 次。

### 3.2 `DocumentFileCopy.kt`
- 将 SAF 的 `DocumentFile` 目录树（`content://` Uri）递归复制到本地 `File` 目录，供推送使用。

## 4. `github` 包：GitHub REST API

### 4.1 `GithubApi.kt`
构造时接收 `token`，内部创建带超时与 `RetryInterceptor` 的 OkHttpClient，请求头带 `Authorization: Bearer <token>` 与 `Accept: application/vnd.github+json`。

公开方法：
- `getDefaultBranch(owner, repo): String` — 查询默认分支（失败回退 `"main"`）。
- `getCommitHistory(owner, repo, branch, count=20): List<CommitInfo>` — 提交历史。
- `getRepositoryFiles(repo: String): List<FileInfo>`（顶层文件树，供预览）。
- `getRepositoryFiles(owner, repo, onProgress): List<FileInfo>`（`?recursive=1` 递归树，供删除选择）。
- `clearRepositoryFast(owner, repo, onProgress, onProgressPercent)` — 快速清空（Tree API 5 步：ref→blob→tree→commit→PATCH ref）。
- `deleteFiles(owner, repo, files, onProgress, onProgressPercent)` — 逐文件 `DELETE /contents/{path}`。

数据类（同文件底部）：
- `CommitInfo(sha, message, author, date)`
- `FileInfo(path, sha, type)`

## 5. `network` 包：网络工具

### 5.1 `NetworkUtils.kt`
- `isNetworkAvailable(context): Boolean` — 检查当前网络是否具备 INTERNET 能力。
- `observeNetworkState(context): Flow<Boolean>` — 用 `callbackFlow` 注册 `ConnectivityManager.NetworkCallback` 监听网络变化（`distinctUntilChanged`）。

### 5.2 `GithubVerify.kt`
- `verify(username, email, token, log): Boolean` — 调用 `GET https://api.github.com/user` 验证 Token 有效性，并比对返回的 `login` 与输入用户名是否一致；邮箱检查跳过。用于配置弹窗中的"确定"前校验。

### 5.3 `RetryInterceptor.kt`
- OkHttp 拦截器：对 5xx 响应与 `IOException` 指数退避重试（默认最多 2 次、间隔 1s 起步），保证网络抖动下 API 可用性。

## 6. `notification` 包：通知

### 6.1 `PushNotificationHelper.kt`
- `createChannel(context)` — 创建渠道 `push_notification`（"推送通知"，IMPORTANCE_DEFAULT）。
- `notify(context, title, message, success=true)` — 发通知，点击跳回 `MainActivity`；成功用 info 图标、失败用 alert 图标，自动取消。

## 7. `platform` 包：Git 平台抽象

### 7.1 `GitPlatform.kt`
- `sealed class GitPlatform`，三个单例子类：
  - `GitHub`（apiBase `https://api.github.com`，默认分支 `main`）
  - `GitLab`（`https://gitlab.com/api/v4`，`main`）
  - `Gitee`（`https://gitee.com/api/v5`，`master`）
- `detect(url)` — 按 URL 关键字匹配平台，默认 GitHub。
- `buildCloneUrl(platform, url)` — 按平台规范补全克隆 URL（处理 `.git` 后缀、无协议前缀等情况）。

## 8. `ui` 包：Compose UI

### 8.1 `MainScreen.kt`
- 主界面 `MainScreen(viewModel, onRequestStoragePermission)`：订阅 `uiState`，`Scaffold` + `TopAppBar`（在线状态指示、菜单：修改配置/推送历史/定时推送），主体为卡片布局（目标仓库/操作按钮/进度/错误/运行日志）。
- 日志区：`LazyColumn` 深色终端风格，按关键字着色（失败红/成功绿/进行中黄），支持自动滚动、复制、清空。
- 内部定义了多个私有对话框 Composable：
  - `FilePreviewDialog`（推送前文件预览与多选）
  - `CommitHistoryDialog`（提交历史）
  - `HistoryDialog`（推送历史，可清空）
  - `ScheduleDialog`（定时推送设置/取消）
  - `DownloadDialog`（下载路径）
  - `SourceDirDialog`（本地源码路径，浏览/手输）
  - `ClearOptionsDialog`（快速清空 / 选择文件删除）
  - `FileSelectorDialog`（仓库文件多选删除）
- 工具函数：`formatTimestamp(timestamp)`。

### 8.2 `ConfigDialog.kt`
- 配置弹窗：邮箱/用户名/Token 输入，Token 密码掩码显示，"如何获取 Token"帮助说明，点击确定调用 `GithubVerify.verify` 校验（带验证日志弹窗与结果弹窗），成功后才回调 `onPositive` 保存。

### 8.3 `ui/theme/`
- `Color.kt`：主题色板（Material3 蓝色系 + 深色背景常量）。
- `Type.kt`：自定义 `Typography`（titleLarge/bodyLarge/labelMedium）。
- `Theme.kt`：`PushGithubTheme`，跟随系统深浅色，`darkColorScheme`/`lightColorScheme`，并同步系统栏颜色与状态栏图标明暗。

## 9. `viewmodel` 包：业务中枢

### 9.1 `MainViewModel.kt`
- `AndroidViewModel`，初始化时 `loadConfig()` + `loadRepoConfigs()` + `loadHistory()`，并 `checkStoragePermission()`。
- 维护 `MainUiState` 的 `StateFlow`（详情见 [02-整体架构](02-整体架构.md#4-状态管理mainuistate)）。
- 公开方法分组：
  - 配置：`openConfigDialog`、`saveConfig`、`updateRepoUrl`、`updateBranch`、`tryGetDisplayPath`、`updateSourceDir`（SAF）、`updateSourceDirManually`、`clearSourceDir`。
  - 权限：`checkStoragePermission`、`showStoragePermissionDialog`、`dismissStoragePermissionDialog`。
  - 推送：`confirmPush`、`startPush`（主流程）。
  - 下载：`showDownloadDialog`、`startDownload`。
  - 清空：`showClearOptionsDialog`、`clearRepositoryFast`、`showFileSelector`、`toggleFileSelection`、`selectAllFiles`、`deselectAllFiles`、`deleteSelectedFiles`。
  - 历史：`loadHistory`、`showHistoryScreen`、`clearHistory`。
  - 文件预览：`previewFilesBeforePush`、`dismissFilePreview`。
  - 提交历史：`loadCommitHistory`、`dismissCommitHistory`。
  - 定时：`showScheduleDialog`、`updateScheduleInterval`、`schedulePush`、`cancelScheduledPush`。
  - 日志：`addLog`、`clearLog`、`updateLogFilter`、`filteredLogs`。
- 私有支撑：`parseRepoUrl()`、`loadToken()`、`insertPushHistory()`、`logExceptionDetails()`、`extractRepoName()`。

## 10. `worker` 包：后台定时推送

### 10.1 `ScheduledPushWorker.kt`
- `CoroutineWorker`，入参常量：`KEY_REPO_URL` / `KEY_SOURCE_PATH` / `KEY_BRANCH` / `KEY_PLATFORM`。
- `doWork()`：读取配置 → 校验 `hasConfig()` → `GitHelper.pushSourceToRepo`（`sourceUri=null`）→ 写入推送历史 + 发通知 → 返回 `Result.success/failure`。
